# figma-reader CLI

Read-only access to Figma files. `<file>` is a local `.fig` path, a Figma file key, or a `figma.com/design/...` URL. When a URL carries `?node-id=`, the commands that take `--node-id` use that node unless `--node-id` is given: `get-tree`, `get-node`, `search`, `token-usage`, `get-text`, `screenshot`, `export-image-fills`. A scoped `search` covers that node's subtree and echoes `searchedNode`; `--page` narrows by page instead. `load-file`, `get-variables`, `get-styles`, `get-components` and `dev-status` answer about the whole file and ignore a node-id.

Run `figma-reader help` for all commands and `figma-reader help <command>` for a command's options. If it is not on PATH, `npx -y @leogcode/figma-reader@latest <command>` works the same and needs no install; from a clone, `node <repo>/dist/cli.js`. Node 22+, and a Chromium-family browser for anything that reads figma.com.

## Workflow

1. Get an overview: `figma-reader load-file <file>` lists pages, node counts, variable collections, styles and components.
2. Find the frame: `figma-reader get-tree <file> --depth 1`, or `figma-reader search <file> "<name>"` (add `--include-text` to match visible copy too).
3. Read it: `figma-reader get-node <file> --node-id <id> --depth 2` for exact specs (geometry, fills as hex, auto-layout, text styles, bound variables).
4. Look at it: `figma-reader screenshot <key-or-url> --node-id <id>` writes a PNG and prints its path. Open that image to see the design. The image is rendered from the live file in the browser, not from a snapshot, so this is the one command a plain local `.fig` path does not answer: it needs the file key, either in the URL/key you pass or in the file's name (`<name> [<key>].fig`), and fails with exit 1 otherwise.
5. Tokens: `figma-reader get-variables <file> --format css` (or `dtcg`, `json`), `figma-reader get-styles <file>`. If the file defines no variables or styles, use `figma-reader token-usage <file> --node-id <id>`.
6. Copy: `figma-reader get-text <file> --node-id <id>` returns every string in reading order, including text inside component instances.
7. Handoff: `figma-reader dev-status <file>` lists the frames, sections and components marked Ready for dev or Completed, and those unmarked since, newest first (`--page`, `--status ready_for_dev|completed|none|any`). `get-node` carries the same as `devStatus`, plus the designers' `annotations` and `measurements`.

## Rules

- Output is JSON or text on stdout; pipe JSON into `jq` to keep it short. Exit code 1 means the call failed (message on stderr), 2 means bad usage.
- Keep `get-node` depth low (1 or 2) on large frames; it refuses results over 200 KB.
- Node ids look like `12:34`; `12-34` from URLs works too.
- Which frames are ready for dev: ask `dev-status`, never guess from names, pages or a missing permission. Quote the raw value beside the name until the mapping is confirmed: "marked `BUILD` (read as Ready for dev) on 2026-10-01". `status: none` with a `previous` other than `none` means the mark was removed at `changedAt`. A never-marked record (none, previously none, no user or note) is not shown by `get-node` or `get-tree`; `dev-status --status none|any` lists it.
- To check several node ids (ones a document or an earlier answer cites), `figma-reader locate <file> --node-ids 12:34,56:78` answers all of them in one call: each is `found: true` with its `type`, `name`, `page` and `path`, `found: false` when the file has no such node, or carries an `error` when it is not a node id. A file that cannot be read fails the call (exit 1) rather than reporting ids missing.
- Each call decodes the file again, seconds for a large one. For several calls on one file, pipe JSON lines to `figma-reader batch`, which decodes a file once while at most four files are in play (group the calls by file), one call per line: `{"tool": "get-text", "args": {"file": "<file>", "node_id": "12:34"}}` (MCP argument names, as `--json` takes them). Each call gets one line back, in order: `{"i": 0, "ok": true, "result": ...}` with the command's JSON (a string for text such as `get-tree`), or `{"i": 1, "ok": false, "error": "..."}`. The exit code is 1 if any call failed; read each line's `ok`. See `figma-reader help batch`.
- `search` queries are case-insensitive literal substrings, so a name with slashes or brackets (`Icons/Arrow/Left`, `/Card [v2]/`) finds itself. Add `--regex` to read the query as a pattern instead, bare or `/pattern/flags` for per-query flags, where an invalid pattern is an error, and `--case-sensitive` to match case. `queryAs` in the result says how the query was read.
- To leave archive or template pages out of a `search`, pass `--exclude-page <name>` (repeatable): it skips them before `--limit`, while filtering with `jq` afterwards loses every hit the limit already cut. The project may skip some by default (`excludePages` in `.figma-reader.json`); the result names them in `excludedPages`, and `--json '{"exclude_pages":[]}'` searches every page.
- `get-tree` spends `--max-nodes` a level at a time. A branch cut short ends in `- ... N more children`, a layer with none shown says `(N children)`, and a layer drawn only with vectors is one line, `(27 vectors)`: pass that layer's id as `--node-id` to see what is under it.
- Calls that need figma.com (a key or URL with no local `.fig`) start a headless browser and take tens of seconds. Exported snapshots are cached for 30 minutes, so later calls on the same file are fast. `--refresh` forces a new export, one that begins after you ask for it; on a path to a `.fig` there is nothing to export from, so it is ignored and the result says `refreshIgnored: true`.
- Every command but `screenshot` reads a local `.fig` path without the browser and writes only what you ask it to (`--out-file`, the directory given to `export-image-fills`), so it works in a read-only sandbox. Calls that go through the browser (the ones above, and `screenshot` always) need figma-reader's state directory writable, and an export its cache too.
- A result that carries a date names it after what it dates. `exportedAt` is when this tool exported that snapshot through the browser: say when the design was read ("as of 14:03") rather than calling what you report current, since after the user edits the file that time is how they tell a cached snapshot from an answer you invented. A `.fig` the user supplied carries `fileModifiedAt` instead — that copy's file time, which copying, syncing or re-downloading resets, so the design can be older than it says. Quote it as the file's time, never as when the design was read.
- `load-file`, `get-node`, `locate`, `search`, `get-components`, `dev-status`, `token-usage` and `get-text` carry either field, and `get-tree` carries it in its first line, `# ` followed by JSON (skip that line to read the outline). `get-variables`, `get-styles` and `export-image-fills` carry none, so do not date what they tell you: take the time from a `load-file` on the same file, or say it is unknown.
- Each project uses one Figma account, set in its `.figma-reader.json` (see `figma-reader accounts`), so run `figma-reader` from the project's directory, not from a scratch directory. A call on a key or URL names the account it went through: `account` in the JSON of `load-file`, `get-node`, `locate`, `search`, `get-components`, `dev-status`, `token-usage`, `get-text`, `list-files --source web`, `status` and `login`, `get-tree`'s first line, the end of `screenshot`'s note, and `[account …]` at the end of an error. `get-variables`, `get-styles` and `export-image-fills` print only the tokens, styles or images, with no account; they are refused like the rest when no account was chosen. If a call refuses because no account was chosen ("no Figma account chosen", exit 2), ask the user which account the project uses and pass only that name with `--account`; never pick one yourself, `default` included. Do not edit `.figma-reader.json` unless the user asks.
- If a call reports that the browser is not logged in, run `figma-reader login` and ask the user to sign in in the window it opens, then retry. If a file is not found or not accessible, the project's account may lack access: tell the user which account is in use rather than trying another.
- `get-text` always reports `unresolvedInstances`, and `search --include-text` reports it when the text pass actually ran — a `--types` list without TEXT turns the pass off, and then the field is absent rather than 0. A non-zero value means some text is missing from the result; `get-text` names the components it is missing in `unresolved`.
